# Бриф для запуска AI-бота Print Cafe

Заполните чек-листы галочками: `[ ]` → `[x]`. Обязательные пункты помечены ⭐ — без них старт невозможен или будет работать вхолостую.

---

## 1. Доступы и технические данные

### 1.1. Wazzup24 ⭐

- [ ] **API-ключ** Wazzup24. Где взять: Личный кабинет → Интеграции → API → создать новый ключ для интеграции «Print Cafe Bot».
- [ ] **Список подключённых каналов** с их `channelId`, типом (WhatsApp / Telegram / Avito / VK / Instagram) и кратким назначением (например, «WhatsApp розница», «Avito B2B»).
- [ ] **Права на настройку вебхуков** — у пользователя/ключа должны быть права на `webhooks` и `messages`.
- [ ] **Тестовый канал** на первый месяц (отдельный номер WhatsApp Business или тестовый Telegram-аккаунт), чтобы не задевать боевые диалоги. Если выделить отдельный номер невозможно — сообщите, договоримся об альтернативной схеме.
- [ ] **Архив диалогов за 1–3 месяца** (желательно). Можно выгрузкой из Wazzup или скриншотами 50–100 удачных переписок менеджеров.

### 1.2. CRM (если используется)

Заполните только тот блок, который у вас есть. Если CRM нет — отметьте пункт ниже.

- [ ] CRM **не используется** — пропустить блок.

**amoCRM**
- [ ] Поддомен (`*.amocrm.ru`).
- [ ] Долгоживущий токен интеграции (или данные для OAuth).
- [ ] ID воронки и этапов: «новый лид» / «квалифицирован ботом» / «передан менеджеру» / «закрыт».
- [ ] ID кастомных полей сделки, куда писать бриф (продукт, тираж, дедлайн и т.д.).

**Bitrix24**
- [ ] Webhook URL входящего вебхука с правами `crm`, `tasks`, `im`.
- [ ] ID воронки и стадий.

**RetailCRM / другая**
- [ ] Документация на API + ключ. Опишите, что хотите видеть в карточке клиента.

### 1.3. Yandex Cloud ⭐

- [ ] Сервисный аккаунт с ролями `ai.languageModels.user` и `ai.embeddings.user`.
- [ ] `folder_id`.
- [ ] API-ключ (или авторизованный ключ) сервисного аккаунта.
- [ ] Привязанный платёжный аккаунт. Если бюджет нужно согласовать — сразу скажите ориентировочный потолок в месяц, мы прикинем под него.

### 1.4. Хостинг ⭐

Выберите один вариант:

- [ ] **Поднимаем на вашей инфре.** Тогда нужен VPS (Selectel / Timeweb / Yandex Cloud Compute) минимум 4 vCPU / 8 GB RAM / 80 GB SSD, доменное имя (например, `bot.printcafe.ru`) и SSH-доступ для нашего инженера.
- [ ] **Поднимаем у нас**, передадим вам после стабилизации. Тогда от вас — данные оплаты и подтверждение, что согласны на временное хранение в нашей инфраструктуре.

### 1.5. Сайт компании

- [ ] URL сайта для парсинга базы знаний.
- [ ] Контакт человека, отвечающего за сайт (на случай вопросов по структуре или если потребуется доступ к админке/sitemap).
- [ ] Если есть — ссылка на актуальный прайс/каталог в открытом доступе (Google Sheets, PDF на сайте и т.п.).

## 2. Контент для базы знаний

Это то, на чём бот учится отвечать. Чем подробнее — тем выше доля автозакрытий.

### 2.1. Каталог продукции ⭐
- [ ] Заполнен `02_products.xlsx` (или прислан собственный прайс/каталог в любом виде — мы перельём в шаблон).
- [ ] Указаны фото / ссылки на карточки на сайте по каждой позиции.
- [ ] Помечены ходовые SKU (топ-10–20), которые встречаются чаще всего.

### 2.2. Прайс ⭐
- [ ] Заполнен `03_pricing.xlsx` — все четыре листа («Цены печати», «Доплаты», «Доп. услуги», «Скидки»).
- [ ] Указано, актуальны ли цены на момент передачи и до какой даты.

### 2.3. Методы печати и нанесения ⭐
- [ ] По каждому методу (DTG, DTF, сублимация, шелкография, термотрансфер, вышивка, УФ, тампопечать, гравировка): для каких изделий подходит, ограничения (мин. тираж, цвета, материал), размер области печати в см.
- [ ] Можно описать в `04_faq.md` в разделе «Макеты и требования к файлам» или прислать отдельным документом.

### 2.4. Сроки производства ⭐
- [ ] Стандартные сроки по типам заказа (футболки 1 шт, футболки 100 шт, кружки, шопперы и т.д.).
- [ ] Что замедляет (товар под заказ, согласование макета, праздники, новогодний пик).
- [ ] Срочные тарифы (1 день, 3 дня) — стоимость доплаты в `03_pricing.xlsx`, лист «Доплаты».

### 2.5. Требования к макетам ⭐
- [ ] Принимаемые форматы (PDF, AI, EPS, PSD, PNG с прозрачностью).
- [ ] Требования к DPI и цветовому профилю.
- [ ] Что делать, если макета нет — стоимость и сроки отрисовки (внести в `03_pricing.xlsx`, лист «Доп. услуги»).
- [ ] Шаблон ТЗ / форма брифа на макет, если есть.

### 2.6. О компании
- [ ] Год основания, опыт.
- [ ] 5–10 известных клиентов / кейсов / ссылок на портфолио.
- [ ] Ссылки на отзывы (Яндекс.Карты, Google, профильные площадки).

### 2.7. FAQ ⭐
- [ ] Заполнен `04_faq.md`. Минимум — разделы «Заказ и оформление», «Оплата», «Доставка и самовывоз», «Сроки производства».

## 5. Что произойдёт, если что-то прислать не получится

Чтобы вы понимали последствия и могли расставить приоритеты:

| Чего не хватает | К чему приведёт |
| --- | --- |
| Нет доступов Wazzup24 / Yandex Cloud | Старт разработки откладывается. Вообще. |
| Нет правил handoff (`05_handoff_rules.md`) | **Не запускаем.** Бот может наобещать клиенту лишнее — финансовый и репутационный риск для бизнеса. |
| Нет тона (`06_tone_of_voice.md`) | Ответы будут «синтетическими», как у безличного бота. Тюнинг займёт 2–3 лишние недели. |
| Каталог только частичный | Бот рассказывает только про известные позиции, по остальным — «уточню у менеджера». Польза есть, но процент автозакрытий ниже. |
| Нет прайса | Любой ценовой вопрос → к менеджеру. Бот превращается в навигатор по сайту. |
| Нет FAQ | Бот будет давать общие ответы или часто переспрашивать. Доля автозакрытий низкая. |
| Нет архива диалогов | Стиль выйдет «правильным, но не вашим». Поправим за 2–4 недели разметкой, но дольше. |
| Нет CRM-доступов | Лиды будут падать в нашу базу + помечаться тегом в Wazzup24. CRM подключим позже. |
